# Building the unsigned IPA

You said you would sign the app yourself, so nothing here needs your Apple
Developer certificate. Every target is configured with an empty
`DEVELOPMENT_TEAM` and `CODE_SIGN_IDENTITY`.

## What this repository can and cannot do

The Xcode project is complete and checked in — `ios/NeptuneRemote.xcodeproj`,
generated by `scripts/generate_xcodeproj.py` and re-generatable at any time.

**Compiling requires macOS with Xcode.** There is no cross-compiler for
SwiftUI/UIKit on Linux. If you run the build script on Linux it exits with
status 2 and an explanation. It will not produce a placeholder file named
`.ipa`, because a fake IPA is worse than no IPA.

## On a Mac

```bash
cd neptune-remote
./scripts/build_unsigned_ipa.sh
```

It will:

1. regenerate the Xcode project from the sources on disk,
2. `xcodebuild archive` with `CODE_SIGNING_ALLOWED=NO`,
3. take `NeptuneRemote.app` out of the archive,
4. wrap it as `dist/NeptuneRemote-unsigned.ipa` (an IPA is a zip with a
   `Payload/` directory),
5. print the SHA-256 and the app's size.

If `xcodebuild` fails, the script stops and prints the error. It does not
continue to the packaging step.

## Signing it afterwards

With a paid Apple Developer account:

```bash
# 1. Unpack
unzip dist/NeptuneRemote-unsigned.ipa -d work/

# 2. Put your own provisioning profile in place
cp YourApp.mobileprovision work/Payload/NeptuneRemote.app/embedded.mobileprovision

# 3. Sign the extensions first, then the app
codesign -f -s "Apple Development: you@example.com" --entitlements widget.plist \
    work/Payload/NeptuneRemote.app/PlugIns/NeptuneRemoteWidget.appex
codesign -f -s "Apple Development: you@example.com" --entitlements share.plist \
    work/Payload/NeptuneRemote.app/PlugIns/NeptuneRemoteShare.appex
codesign -f -s "Apple Development: you@example.com" --entitlements app.plist \
    work/Payload/NeptuneRemote.app

# 4. Repack
cd work && zip -qr ../NeptuneRemote-signed.ipa Payload && cd ..
```

Tools like **Sideloadly**, **AltStore** or **ESign** do all of that for you —
hand them `dist/NeptuneRemote-unsigned.ipa`.

## Identifiers you will want to change

| Setting | Value | Where |
| --- | --- | --- |
| App bundle id | `com.neptune.remote` | `scripts/generate_xcodeproj.py` → `BUNDLE_ID` |
| Widget bundle id | `com.neptune.remote.widget` | derived |
| Share bundle id | `com.neptune.remote.share` | derived |
| App Group | `group.com.neptune.remote` | the three `.entitlements` files **and** `SharedStore.appGroupIdentifier` |

The App Group must exist in your developer account, or be removed from the
entitlements. Without it the app still runs: `SharedStore` falls back to standard
`UserDefaults`, the widget shows placeholder data, and the Share Extension
reports "the shared container is not available in this build" instead of
pretending to have saved your file.

## GitHub Actions

`.github/workflows/build-ios.yml` runs the same script on a macOS runner and
uploads the IPA as an artifact. It runs on every push to a `claude/**` branch,
on pull requests, and on demand via *Run workflow*.

Because the runner also has Python, the workflow additionally runs the backend
test suite and `scripts/verify_project.py` — so a red build tells you something
real broke, not that the runner lacked a certificate.
